## 控制拍状态与覆盖算式

每个计划拍为左右臂和左右手保留四组状态位与原因为审计列，同时仅给全身分配一个主状态。`q_issue(t)` 需为当下因果计算并通过独立接纳的 54 轴命令。验证联合/手部驱动范围、姿态/速度、名义与滤波路径、J6/J7、全身/跨侧碰撞、有限性和权限。检查所有实际候选子步及首末状态，防止只检查最后关节向量。跟随合法静止时允许 `q_issue(t) = q_issue(t−1)`，但须本拍重新接纳且独立 FK 验证 provider 原请求的组误差在完全跟踪容差内。对手而言采用本拍得到或合法重复且重新接纳的 Wuji 名义关节目标，经源和指序核验，数值参照同一关节重算容差 `1 µrad`。本拍仅靠复用旧命令或流程跳出的数值相等不取得信用。

| 主状态 | 必要证据与名义覆盖信用 |
|---|---|
| `ACTIVE_TRACKED` | 四组本拍均通过新鲜度、有效性、SDK 和独立接纳。未触发任何改变目标的限速、workspace、缩步、轴投影、安全或分组部分命令；原 provider 请求在独立 FK/有名关节核验中满足跟踪重算容差。四组按状态机合法保持在目标点的零变化同样可计入。覆盖信用 1。 |
| `LIMITED_ACTIVE` | 四组仍基于本拍合格请求，优先使用同拍其余已跟踪的组，再以明确记录的限速、workspace、缩步、轴投影或安全裁限解决剩余组，并独立接纳全身路径。受限组的参考步骤需由当下目标产生。记录上次接受位置与当前接受位置的变化、对原 provider 请求和本拍中间目标的误差。若至少一个受限组没有可分辨命令变化且仍未到达该组原 provider 请求，整拍无主动覆盖信用，按 `HOLD` 或 `FALLBACK` 归因。防止最大限位停滞、数值抖动或固定回退被计成有效运动。覆盖信用 1。 |
| `HOLD` | 缺少源输入、源过时、当前请求未获得接纳或已到达约束边界但仍有显著请求差时，复用上次有名合法命令并复验安全。包括单组 hold 而其他组可运动的情况。数据校验成功但仍在冻结恢复宽限期也单列 `HOLD/RECOVERY_WAIT`。覆盖信用 0。 |
| `FALLBACK` | 控制保护明确选择并安全接纳另一有名策略产生的命令，例如受限停止或回安全姿态。以前次命令为 fallback 需保持 `FALLBACK` 原因，普通 hold 仍单列。若任何组使用这一保护路径，整拍无主动覆盖信用，其他组可以独立诊断。覆盖信用 0。 |
| `FAILED` | 输入、依赖、求解或硬检查错误且未下发受认可的 hold 或 fallback，或者追踪缺失、硬违规、超时，或无法独立重放接纳。区分 `UNKNOWN`、`NOT_RUN`、输入不适用及实际运行失败的原因，未验证命令不给信用。覆盖信用 0。 |

主状态冲突按失败、回退、持有、受限主动、主动跟踪的顺序保守裁定。保留独立布尔列 `exact_direct_arm[2]`、`raw_valid[4]`、`accepted[4]`、`limit_applied[54]`、`held[4]`、`fallback[4]`、`path_pass` 和 `command_changed[54]`，防止分组成功掩盖双侧失败。受限组变化以有名关节重算容差 `1 µrad` 为可分辨下限；所有变化须能归因于已存证的候选路径且独立复算。把限速作为 `LIMITED_ACTIVE` 的子类另报，同时列出实际限速但未获得主动信用的原因。保留同一命令被拒绝后的原始 SDK 提议和全部重试结果。裁限类别覆盖可以重叠，主状态应互斥且全量守恒。

## ±8° / ±5° 的独立几何与 Servo 见证

对每一个正式参考域行使用同一冻结 54 轴名义 q 和 M1，定义 `E(q,t)=1000 max_i ||tip_i(q)-mapped_tip_i(t)||₂`，单位毫米。有限候选使用 arm `|q−q_nominal|≤8°`、hand `|q−q_nominal|≤5°` 按有名轴裁限，固定原审批局部 Jacobian 搜索顺序、seed 49 及每拍最多 8 个尝试。候选本身须满足有名关节、执行器、耦合、碰撞间隙与 `q_nominal→q_w` 的硬路径证明，独立 MuJoCo CPU FK 复算 `E`、几何单位和索引。记录搜索失败、到达尝试上限、缺少合法名义、未运行、严格必要条件排除及已知合法见证为不同原因，对未证实的结果记 `UNKNOWN`。原 M1 名义目标参考保持完整。

## 运行顺序与独立收据

先封存候选代码、模型、SDK、时钟和安全的输入哈希及准入函数，使用 Train 定标一次。锁定后对全部 308 个分区核对计划行守恒，Validation 不允许反向调参或重切分。核验部署两包 SHA 及亲缘隔离，原 HMB 保持只读，不删除历史派生条目；任何不允许进入学习的来源记录为禁采和按原分母可追踪。实际运行索引需包括 PID、命令、日志、退出码、所耗预算和源码 SHA。每个结果附 `attempt` 哈希，保留失败和修订。至少 512 行按源分层独立复算，各失效原因全部或至少 16 例且包含极值与边界，至少 64 个见证；同时覆盖 32 根的前缀验证及计数和零残差复算。证据目录应至少包含逐拍状态及路径 trace、覆盖汇总、见证账与因果负控、在线适配差异及源码/数据/预算清单。只有正负控和证据身份可复验后才提交独立技术意见供人工审批，审批前无正式新合同、数据发布或下游解锁。
