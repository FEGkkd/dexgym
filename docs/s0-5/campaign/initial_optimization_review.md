- 独立读回两份 Native MuJoCo smoke JSON。各执行 136 个实际仿真 transition，均为一个实际并行环境及合成目标。相关进程退出 135，两份记录共 272 transitions 应计入 B/C0 前置消耗。对应 SHA-256 分别为 `8ca101dbf9d7fd4ea39170be008fb35ec3ba1ca1fffd99ce1d0b1223b11c5c5e0` 和 `f4f99b9945d6badfc521c4a375ae6ea40692b7dc4b2724192f390a2e94e0cbad`。清洁退出、物理等价、签名 RMB 接线与规模爬梯待验证。
- RTX 5090 的 PyTorch 有限输出和 Warp 末元素 62 已记录。探针进程退出 135，实际批量 World Model 更新和整体 learner 吞吐均未取得资格。唯一持久设备 `nvme0n1` 记录多个不可恢复读取错误。恢复需先核验健康存储和运行依赖。

## 资源下限

4096 环境、UTD 0.5 时，每轮采集 8,192 transitions。30,000 轮产生 245,760,000 transitions。一次 66 拍暖场消耗 270,336，主线 250M 上限剩 3,969,664 用于暖场以外的额外收集，包括小试、失败和恢复。C0 的已记账主迭代和额外收集分别归账。B/C0 前置 10M 子上限与 30,000 轮目标同时约束，不能把该子上限当成主线上限外的配额。首阶段最多 50M，扣除一次暖场且余下开销为零时最多容纳 6,070 轮。C2 和 C3 各 100M 同样最多 12,207 轮。阶段最终推进仍取决于技术门。

48 GPU 小时内完成主目标和一次暖场所需的实际采样均速约为 1,424 transitions/s，已包含该时间内的模型更新等竞争。若全额 10M 评估另占用同一 GPU 时间，以合计物理步数计算的均速约为 1,482 transitions/s。此为计量下限，包含数据、优化器、诊断和作业间开销的实测吞吐仍待取得。运行计时须保留独立阶段成本和已有资源消耗。

每 250k transitions 触发一次独立 watchdog。在主目标及一次暖场下，保守规划约 984 次周期性触发，每次至少 256 个起点。若 1/4/8 步来自同一条 8 步真实轨迹，至少耗用 2,015,232 次实际评估拍。5.5M 训练期评估池剩约 3.485M。忽略阶段转换、异常触发和重验时，30 次千轮评估每次可用约 116,159 transitions。若另行分别执行 1、4、8 步，每次消耗更多，必须按实际重复记账。D3 最终预算已有单独预留。

## 检查点与恢复顺序

1. 在健康持久路径上读回归档、运行依赖和签名资料，重跑 64 环境小试及所有清洁退出检查。先排除已有进程与路径覆盖。
2. 从原始 M1 与保留的右臂失败样本执行正反运动学对照，核对有名轴、软件安装、目标坐标、合法运动及工作空间。继续使用原阈值规定的口径和同源统计；连续性失败由已授权的平滑候选及独立 G-A 资格处理。
3. 运行 B 的签名 RMB 联调、CPU/Warp 等价、安全及因果负控，再测 64→256→1024→2048→4096 各档实际物理、投影、质检与显存。在足够吞吐和独立证据下选择正式环境数；失败档次和可接受降级单独记账。
4. 取得独立 C0 资格后才能启用 Actor/Critic。当前 C0 入口只运行 pre-Actor 拟合，独立 G-A/G-B 收据绑定已在源码中接好。World Model 的静态、真实差分、边界与独立物理 watchdog 仍需执行。C1–C3 runner 还需接入原分阶段门和训练期验证。
5. 通用引擎保存模块、优化器、种子与可选 sampler。当前 pre-Actor 入口仍从初始化开始，缺少实际恢复参数和 checked 消费流水。它标记 `RESUME_REFILL`，尚需加入绑定 Git、配置、RMB、模型、Servo 和预算余量的恢复校验，并实测填回 Replay 消耗、原迭代单调增长、终止后的 checkpoint 回退。当前台账登记了配额和证据，运行前的原子预留／失败及复验的实时记账仍需接入；仅凭 CLI 的保留数值无法证明记账。
6. Replay 环覆盖修订已保留原始行并拒绝缺少前驱的情形。应在健康环境跑新版逐元素测试，覆盖有效后半窗、源和世代边界、陈旧行及失败记录。采集与评估需要真实 MuJoCo 记录，日期和轮数只作监督索引。
