# DCR-001 拆分 P01 人体数据与真机遥测依赖

## 决定与授权

DCR v1。原设计基线为 `f32d6bbfc4f535a5c53db1025a484e48fc5f2ce3` 和 P01 Spec v0.2.0。项目用户通过当前 **S0-5 P01-B Independent Review Fix & Dependency DCR** 明确批准此依赖调整及实现核查。该授权针对依赖关系。各技术门、P01-C 开工、P01-T 实际采集、P03 和训练分别需要独立证据及授权。

## 原设计、发现和证据

v0.2.0 把适用格式解码 B1、真机遥测 B2 当成 P01-B 同一组前置门。已认可的 attempt-04 在 14 个录制得到 21,321／21,440 条成功解码。旧 merged `CollectionStatus` 失败 119 条。B2 缺独立真实硬件、命令—实测反馈配对及时钟证据，37 个去重视图缺硬件证明，动态候选为 0。人体原始拓扑、双腕、标定来源以及 recorder 的关联记录可独立判定。[原审核](../reports/P01_B_acceptance.md) · [本轮复验](../reports/P01_B_review_fix.md)

## 变更与验收

- 人体线采用 P01-A → P01-B-HMB → P01-C → D → E → F。A 接受元数据，B-HMB 接受真实有界核心解码，C 验证标定、单位与因果，D 冻结 QC 和 split，E 构建，F 独立验收。P01 退出需 F 和整体人工签核。P02 正式启动依赖该验收及其原有前置条件。
- 平行设置 P01-T。Telemetry B2 仍是一项未履行的技术门，P01-T 保留独立状态、来源取证、资格及补录计划。P03 正式启动须同时满足 P02 ACCEPTED、P01-T 资格门通过及人工 ACCEPTED，以及原有模型和实验前置条件。正式 RL 和硬件对齐 Servo 的主张需实际测量及后续各阶段验收。
- 按 [Topic Dependency Matrix](../specs/topic_dependency_matrix.md) 区分核心、依赖特定证据的条件消息、遥测和诊断。若录制的唯一合格来源、完整性、有效性、安全或同步证据来自辅助类型，按必要证明处理，解码缺失则持续隔离。
- P01 历史 B1 FAIL、B2 BLOCKED、attempt-04 和失败日志永久保留。新 HMB 技术门、辅助 schema 复验、P01-T 资格和人工状态分别登记。独立 Final Test 仍为 BLOCKED，封存、访问记账及 P09 的门保持生效。

## 替代方案与风险

维持同阶段全通过会使与真机数据无关的 P02 人体意图工作等待实机补录。仅跳过 B2 会丢失硬件 Servo 与真实响应的必要证据。两条线各自验收可保护 HMB 研究，并保留 P03 前的硬门。主要风险是把有界解码误当完整采集质量、把可读命令数组误当物理响应，或者新源使用默认诊断类别绕过必要来源。分别用样本范围、P01-C/D/F 门、逐源依赖和 P01-T 物理验收控制。

## 影响与兼容性

影响 S05-REQ-001/011/012/015/029/030 和 P01、P02、P03、P04/P05/P08/P09 的前置证据。已更新活动 [P01 v0.2.1](../specs/P01-data-v0.2.1.md)、[P01-T](../specs/P01_T_telemetry_acquisition.md)、主设计、契约、路线及阶段验证器。P01 v0.2.0 文件和历史结果继续适用其冻结的原运行。54 DoF、因果实时、精度、强传统基线、鲁棒、安全及 Final Test 指标和门槛保持。
