# S0-5 Multi-Agent 自主研发协议 v2.0.0

状态为 `DRAFT_READY_FOR_REVIEW`。本轮工作范围为 Design Revision，输出设计与检查证据。本轮结束于 `DESIGN_READY_FOR_REVIEW`。V1 运行须在设计获批后取得项目用户单独的一次性有界 Campaign 授权。[项目状态](PROJECT_STATE.md) · [路线与依赖](ROADMAP.md)

## G1. 职责与工作包

| 角色 | 责任与证据 |
|---|---|
| Main Agent | 读冻结设计和实际仓库，验证授权、DAG、预算和资源，分派互斥写范围，督导进程，集成和复验，处理独立审查发现，按门自动推进并封存。必须把核心模块实现、测试与独立审核分配给不同代理。 |
| Data Agent | 冻结 HMB/RMB 谱系、名义 SDK/IK 输出、输入注册、因果连续性、分母和困难域。 |
| Physics & Task Agent | 实际仿真物理、动作有名双射、安全、Observation、Reward、终止语义和 SuperMimic task adapter。 |
| World Model & Training Agent | 实际 Replay、动力学模型和独立 holdout、想象滚动、Actor/Critic、课程和检查点。 |
| Deployment Agent | 独立实际仿真链路、导出、运行时和 release artifact。 |
| Independent Reviewer | 复核实际源、数据身份、数学和原始日志，独立重跑代表性正负控和实际门，复算统计、失败分母与资源账。Reviewer 不得是被审核心模块原作者，可按专题设置多个独立 Reviewer。 |

分派时登记 `agent_role`、`task_scope`、`input_commit`、读写路径、依赖、冻结接口、实际运行命令、预期正/负控、阶段证据、退出码、剩余问题和交付 SHA。建议独立 Git worktree 或显式独占路径，共用配置与阶段账由 Main Agent 归并。所有失败和重试使用新 Run ID 和不可变目录。每阶段提交 `agent_work_manifest.json`，注明实际执行者、集成者、独立复核者，未运行填 `NOT_RUN`。对本次 Design Revision 使用同样文件所有权和独立审核，活动工作限于文字、源码审计、历史证据核验和检查器合成状态。

## G2. 技术状态与人工权限

技术值为 `NOT_STARTED`、`IN_PROGRESS`、`FAILED`、`BLOCKED`、`TECHNICAL_PASS`、`READY_FOR_REVIEW`。人工设计决定、一次性 Campaign 授权、最终用户验收和硬件/终评授权分别记录。历史 `ACCEPTED` 继续用原版本的凭据验证。当前设计候选批准为 `PENDING_HUMAN_REVIEW`，执行权限为 false，V1-A 至 V1-D 为 `NOT_STARTED`。

未来授权记录须引用真实项目用户动作、批准设计 hash、scope、budget hash、批准者、时间、证据链接、限制和撤回状态。Main Agent 复核引用原始批准凭据。技术负责人仅能登记技术状态，报告、状态 JSON 或合成测试凭据均不能赋予权限。正式设计批准与 Campaign 启动授权可以是两条独立人工事件。更改设计、权限、预算或阶段作用域须新批准并绑定相应版本。

启动每个工作包前在同一事务核对授权活动状态、作用域和对应版本、不可变依赖门、独立 Reviewer、预算剩余额度与实时资源。取得 Campaign 授权后，B 的合成输入准备可与 A 并行，正式 G-B 须以 A 合格 RMB 实际联调。C0 依 A 与 B 技术通过。C1–C3 Actor 更新逐阶段推进，并持续具备有效 C0 资格。正式 D 依 C3 技术通过及独立证据。正常技术通过且上述条件仍满足后，Main Agent 可推进下一个 V1 阶段，技术事件与人工事件分开落盘。设计评审、最终用户签核、独立 Final Test、正式物理评分、生产 Teleop 集成、真实设备和运动许可按各自独立前置控制。

## G3. 持久化台账、监督和恢复

建议 `campaign/<campaign_id>/ledger.json` 原子写入快照，并用只追加 `events.jsonl` 记录事件序号、上个事件哈希、时间、角色、旧值/新值、实际引用、预算变动和提交。快照字段至少包含 `campaign_id, approved_design_sha256, authorization_ref, budget_sha256, active_task, dependencies, agent_packages, gate_evidence, active_run_id, checkpoints, progress, resource_usage, retry_used, remaining_budget, next_legal_task, blocked_reason, last_event_seq`。单 writer 锁与异步运行者独占日志避免竞争，账本记录路径与 SHA。状态重建从最后一条通过身份校验的事件继续。

对实际运行记录 host、工作树、命令及启动方式、PID、启动时刻或进程身份、stdout/stderr、日志更新和终止码、设备、配置、源/资产/检查点 SHA、最后已落盘 transition 计数及恢复方法。磁盘、GPU 与进程读数按实测登记。中断后先检查原 PID 标识和日志心跳，核对 checkpoint 与 replay/优化器、账本计数与真实命令。活进程仍在运行则重新接管监控。进程退出或状态矛盾时保存原状并审计恢复点，允许有授权的非逐拍恢复时记录状态差异和资格影响。恢复后从新 Run 续记，启动门必须重新执行。进度使用可验证运行状态及数据，预计耗时只作资源规划依据。

每次循环按冻结 Spec、实现、实际实验、独立复核、决定推进。复核比较代码、数学、固定输入、原始观测、输出和负控，核对置信区间、下游影响与证据路径。发现按严重度保存，指定修复人和重验人。关键问题阻止通过，修复不得覆盖旧记录。完成整条技术路线后封存证据，提交 `READY_FOR_REVIEW` 与实际部署技术等级由用户审核。

## G4. 预算提案与执行计数

以下参数为 `PRE_REGISTERED_CANDIDATE`。审批后构成上限，只有单独批准可提高。任务开始前检查该主机实际可用 GPU、显存、吞吐和磁盘，历史 S0-4 64 环境只用作初始规模。使用已授权有界预检记录实际物理 steps/s、更新耗时、吞吐、峰显存、replay 与磁盘占用，据实决定环境数和可执行总量。20M 训练加 2M 评估若全用 48 GPU 小时，平均约需 127 实际 transitions/s，模型更新和导出等占用将提高预检目标。可降低并行度或在上限内缩减探索，以过门证据为准。资源不足就等待或记 `BLOCKED`，不终止其他用户进程。

| 项目 | 候选上限与口径 |
|---|---|
| B54 训练 | 主种子 1 个，最多 20,000,000 MuJoCo 实际环境 transitions。V1-B 实际训练 smoke、V1-C0 预热/探索与 C1 静态共用 2,000,000 的首桶，其中 B smoke + C0 最高 500,000。C2 动态 8,000,000，C3 混合与迭代 10,000,000。 |
| 独立实际评估 | 2,000,000 MuJoCo transitions 另计，候选分池 700,000 C0 资格与模型核验、650,000 C1–C3 监测、650,000 D 选择与发布。运行未进入 replay 的真实环境拍仍按运行目的计到对应池。 |
| 想象与模型更新 | 单独记 imagined transitions、WM/Actor/Critic 更新数，记录 UTD 与实际采样比，受时长与试验预算约束。 |
| B14 | V1 首版提案不分配 B14 训练预算。后续预先申请独立预算或按项目用户已明确批准的分配运行。 |
| GPU 和总时间 | 并发占用上限 1 台 1 卡，最多 48 GPU 小时，含重试和空转占用。Campaign 总经过 72 小时，资源等待累计最多 24 小时，均以单调记时及日志复核。 |
| 存储 | 净新增持久化上限 250 GiB，预检计入模型、replay 快照、历史证据不可替代件及候选导出峰值。只有可再生副本可按预登记保留策略清理。 |

资源账计入已花、运行预留和可用余额。每次运行先预留，结案按实际核销；崩溃和重试已消耗的预算保留。物理 transition 是每环境已经调用并完成的一个控制转移，包含进入失败或截断的最后转移，不能把 reset 或想象计入物理预算。不得用跨桶重试或改种子刷新上限。每次登记预算剩余和允许的下一任务。受硬限制时采用退出或已有 checkpoint 封存。

## G5. 有界迭代和再资格

下表可调范围仅在批准的 Campaign 内生效。若阶段规格和参数登记更窄，取更窄限制。每阶段最多两次验证重试，C0 最多三项模型定标候选，C1/C2/C3 每阶段最多两项学习变体且计入主预算。回滚、修复和复验均留记录，禁止并发无界搜索。每次记录假设、代码和 config 差异、原始试验预算、保持的对照、执行人、证据及审查结论。

| 类型 | 候选授权范围 | 必须重验 |
|---|---|---|
| 代码、数据转换、接口 | 修复可定位 bug，冻结 HMB、来源 split、评分目标和独立规则。更新内容指纹，记录影响拍与回滚点。 | 有因果/动作/Servo 变化时重验相应 A/B 门和端到端回放，并使依赖它的 C/D 证据失效。 |
| GPU 效率 | 在预检与账本资源约束内变更 batch/设备调度、编译或数值实现，保持用途与合同。 | 观测、行动、reward、真实物理、梯度和恢复等价。AMP 命中非有限或误差超限则回退。 |
| 学习率及奖励 | WM/Actor 学习率分别在冻结初值 ±25%；正向组权重相对初值 ±25% 且沿用奖励归一化和 value bound。具体代价只按阶段注册范围调整。 | 奖励单调、零动作、早退负控和 value 契约；新配置独立物理对照。奖励不改正式评分。 |
| WM horizon 与探索 | horizon 候选 4/6/8，切换需 C0 按实际 horizon 再资格。探索噪声最多在冻结尺度 0.5–1.5 倍并满足安全包络，实际物理作用、饱和、覆盖复验。 | 真实动态 1/4/8 步诊断、局部敏感性、边界、holdout、漂移和 anti-exploitation。超出 WM 资格时暂停 Actor 更新。 |
| 课程与选择 | 在冻结 Train split、安全和难段定义内，课程各组相对候选增减至多 15 个百分点，保持必要覆盖。按预登记评分和资源选择或恢复 checkpoint。 | 样本谱系、覆盖、静态和动态保留、完整物理回放。恢复需验证 checkpoint 身份及真实预算。 |

关键改变含研究方向、HMB、split、评分目标/掩码规则、V1 性能门与终局挑战、安全裁决权、总资源或真实硬件权限，须独立人工批准。只允许在批准的工程候选范围和冻结时点选择 C0 等数值。影响核心合同后阻断依赖任务，撤销已过技术状态的派生资格并复验全部受影响结果，旧证据照录。

## G6. 停止、失败和权限负控

出现数据身份/split 错误、因果缺陷、物理执行/轴顺序/安全错误、WM 不合格、持续模型利用、关键独立审核未解决、预算或资源耗尽、需更改核心设计、需操作真实机器人或用户要求停止时，立即阻断相关任务和下游，记录实际证据、所需批准和剩余预算。允许在批准范围内修复后重验。安全功能合格但 V1 性能门失败时，保留诊断并可交付实际通过的较低部署等级。

状态检查器用完全合成或只读离线副本验证：当前设计没有执行权限；有权但依赖未过拒绝；有权且依赖技术门过可推进；预算超限停止；硬件资格缺失拒绝真实发布；修改历史批准凭据或门的 SHA 拒绝；人工批准字段由技术 Agent 写入时拒绝；Reviewer 身份与核心作者冲突时拒绝。正负控输出不得写回历史凭据、运行器或真实 stage state。[V1-D](specs/V1-D_evaluation_deployment.md)

验证过的执行上下文须由独立审核来源登记，技术收据绑定输入 fingerprint 和父收据。fingerprint 覆盖实际 RMB、模型/Servo、安全、adapter、评分配置及相应阶段产物。C0 初次收据在相同契约、适用域和启用 watchdog 下可覆盖常规 WM 权重更新；每个新 checkpoint 都留当前独立探针与持续适用证据。适用范围变化、watchdog 失败或必要输入变化时撤回当前上下文，重验 C0 和受影响的下游。V1-B 前置未满足时，授权只允许合成准备和约束内 smoke。
