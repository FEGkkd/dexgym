# S0-5 Multi-Agent 研发协议

适用具有可并行独立工作的 S0-5 阶段及有界补证。代理的技术意见不改变项目用户的阶段授权。每个 ACCEPTED、后续正式开工和现场操作都按已有依赖与审批执行。[总体设计](MASTER_DESIGN.md) · [接口契约](CONTRACTS.md) · [阶段状态](PROJECT_STATE.md)

## 分工与冻结

主代理在开工前核对授权、Git 状态、上一阶段证据和当前 Spec，确定实验依赖，冻结输入 SHA、配置、样本、解算预算与成功和失败分母。在具备独立工作时安排至少三个有实质任务的子代理。每个工作包登记可写路径、只读输入、依赖、验收条件、独立 Run 路径和交接接口。主代理负责依赖解析、冲突裁决、集成、复验及统一报告。一个代理负责代码时，另一个代理可在冻结接口上并行撰写测试、做实验或审计。

可写范围有交集时采用独立 Git worktree，或由主代理明确移交后再写。独占文件范围可共享 worktree，禁止无协调并行写核心文件、配置、发布索引和阶段状态。资源密集试验按真实资源选择顺序或并行，日志和中间产物按 Run 隔离。失败重试保存原文件、原配置和判定。源只读提取同样保存输入路径、采集方式、是否与提交相同和字节哈希。

## 独立审查和证据

独立 Reviewer 不参与其所审核实现的原创。先核对计划、源码和独立数学或工程依据，再按试验输出检查分母、反例、边界、真实运行证据和剩余风险。发现冲突后由实现主责修复，Reviewer 重验，保留问题与变更。代理数量和一致意见不构成技术门证据。

每个阶段在专用 evidence 路径保存 agent_work_manifest.json，并链接独立证据文件。每个工作包含 agent_role、task_scope、input_commit、read_ownership、write_ownership、engineering_basis、actual_commands、positive_tests、negative_tests、findings、remaining_uncertainty、output_paths 和 output_sha256。另记执行者与集成者、路径 SHA、返回码和可用日志来源。命令若由主代理在服务器代执行，工作包注明实现、独立验证与服务器执行各自的责任。没有真实运行的项写 NOT_RUN，缺独立前置写 BLOCKED。源码证据和实际硬件输出分别记账。发布前主代理检查工作包是否遵守独占范围，复读证据哈希、技术门和批准记录。

## 停止与审批

阶段职责与前置以当期主设计和阶段表为准。交接候选保留原资格与原失败。物理运动和现场发令须单独批准并由具备权限的现场负责人管控。证据封存后主代理提交人工审批，技术完成不触发后续阶段。
