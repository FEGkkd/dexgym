## MuJoCo 备用方案的有效范围

本地运行了 MuJoCo 虚拟固定 site 对照，并独立核对 Ubuntu 使用准确模型支撑的回执 SHA-256 `4798dfbdaf80178b265a0c325bce1b96b09221d35b4b11c86d35c650c5f3782a`。三个独立虚拟点的最大位置与方向差为 0。左右调换、水平轴反向和反射负控均拒绝。结果作用域为 `VIRTUAL_SCENE_COORDINATE_CONVENTION_ONLY`，人体录制朝向、装夹和物理标定资格仍为 `false`。固定虚拟标准可约束仿真端的重力、左右与前向，并为机器人轴、FK 和 Home→START 的软件验证提供输入。将该标准应用到历史房间还需要能绑定原记录的方向和人体对应点的证据。再次从机器人实测 q 或同一套虚拟点推算人体外参，会失去人体目标的独立性。[虚拟坐标审核](../../../scripts/s0_5_campaign_teleop/dcr009_virtual_axes.py) · [标定证据](../campaign/DCR-009_calibration_evidence.md)

独立核对了实际 Ubuntu 158 组静态 FK 探针收据，SHA-256 为 `1d67a6dad1831574af10a1fdf6349638097af6457e9d8527c9bd77e150e876fe`。两模型的 54 个有名局部坐标均一致，Home 关节向量的最大差为 0，两侧具名基座与评分腕 TCP 的最大位置和 SO(3) 差也均为 0。模型掌部刚体原点最大位置差为左 0.3001 mm、右 0.2502 mm，超过该次 0.1 mm 位置一致性门。世界系指尖最大欧氏差为左 6.7029 mm、右 5.8170 mm，掌局部最大差为左 6.7885 mm、右 5.8299 mm。

初次模型收据未配置 Marvin 原生工具桥。主代理随后用审阅过的实际 Teleop 源和本机厂商库重建桥接并运行独立扰动。补充收据 SHA-256 为 `f97fa5fe4d907a46fa24b6484278d5d837cd7aaf92df910c9321eb228def0145`，每侧 14 个独立扰动均通过。最大位置与旋转差为左 `2.1432×10⁻⁷ m`、`9.2920×10⁻⁷ rad`，右 `1.9731×10⁻⁷ m`、`6.0573×10⁻⁷ rad`。其适用范围是 live 模型与 Marvin TCP 的静态桥接。人体侧外参、跨模型指尖、接触、控制动态和沿程安全仍有独立证据要求。

同一刚体矩阵可以保证已构造几何的左右相对关系。输入掌根的准确性由独立标定证明。校准未知时，软件配置下的 Tracker 对照可以作为带明确假设的诊断值保存。正式 Pilot 需要给资格回执分开登记虚拟世界、OpenVR 记录端参考、两侧人体解剖附件、机器人侧 FK、两模型范围和适用母源。缺失的记录端校准仍待核验，原 85% 及 70% 门没有新结果。

## 代码与安全边界

- 选择器限定 Train，按签名时戳、来源实例、采集和到达上界及同世代检查稳定窗。存在但不合格的事件无法回退为重建。回放启动前校验权威范围、六个独立根的名单及哈希、机器人资产、固定会话映射、原生服务和隔离 ROS 图。实测 Home 和 START dwell 分开，后者使用推进中的实测 header。该设计可用于复核源代码和合成输入，当前没有新的历史 Pilot 观测。[选择器](../../../scripts/s0_5_campaign_teleop/home_anchored_start_anchor.py) · [运行器](../../../scripts/s0_5_campaign_teleop/replay_home_anchored_pilot.py)
- 启动器在拉起 MuJoCo 进程前核对 `MUJOCO_ONLY`、`QUALIFIED`、明确的历史录包适用资格，以及独立整身发布守卫。回放入口在发出历史输入前重复核验。形式有效的矩阵与完成的虚拟场景测试无法单独证明每个历史母源的适用性。软件复用已经注册的 Tracker 位置可继续用于按原标签对照，避免混入未获资格的解剖几何。
- 已审程序依赖当前 native 安全信号和反馈守卫。正式入场仍需签名模型及 live 模型的全身碰撞和扫掠路径独立证据。旧原生诊断中，同批 399 个命令端点有 154 个被签名模型拒绝，另有 9 个仅由 live 模型拒绝，说明两个模型的端点及路径都须重新核验。新 overlay 仅增加映射与控制器诊断字段，尚未捕获 driver 接纳、生效子步或 `q_applied`。`ACCEPTED`、`LIMITED`、发布包和实测反馈各有独立含义。[旧整身检查](TELEOP_native_nominal_replay.md#signed-whole-body-path-shadow) · [拟议执行契约](../specs/V2_1_home_anchored_runtime_proposal.md)

本地 18 项 Pilot 和 anchor 单元控制通过。首次以 Windows 原生解释器整组读取时，纯选择器测试导入了生产 HMB 模块依赖的 POSIX `fcntl`，因此无法加载。复验只为该纯单元测试提供内存导入占位，未执行 HMB 锁或 ROS 操作。隔离 Ubuntu 使用原生 POSIX 模块再次运行，18 项全部通过。实际标定处置检查退出码为预期的 2，Ubuntu CAL 收据 SHA-256 `9af50a774a80029f91e74c983c15270eb76a1b334a0b2703bdd022bf4a5f08c5` 保留虚拟坐标 `PASS` 和原录包 `BLOCKED`。以上检查未运行任何历史轨迹的物理回放。

## 仍缺证据

合法主动覆盖及因果五拍仍使用各自签名原分母。该阶段没有合法筛选后的六源 Pilot 轨迹，分子为 `NOT_RUN`。不得将这次校准阻塞记成六个实际 START 失败。获准的虚拟验证和已有历史结果继续封存为各自范围的证据。真实 Pilot 的授权和记录端资格是两件不同的事。解除本次阻塞需要有证据的历史记录端对应、拟议临界条件和签名的整身接纳路径。任何另设的软件配置诊断路径须标明替代假设、可用指标和单独授权范围。
