## 证据责任与边界

数据负责人优先查找原包、录制期配置、手臂 Marvin 和双手 Wuji 的型号及匿名设备 ID、驱动/FW/构建哈希、生命周期记录、控制器地址映射、失联和安全事件、标定及实际现场运行日志。每条断言包含原包/分片 SHA、身份来源和记录索引。人工证词可增补来源链，仍需设备、记录和独立时钟观测。分析负责人验证物理与时钟语义，硬件安全负责人批准任何现场操作，项目用户单独签核。当前 37 个去重视图缺硬件证明，动态资格为 0。

现有 `telemetry.py::verify_attestation` 校验 SHA、artifact role、录制 ID 及原始文件组绑定。它不能确认文件里的设备事实。现有 `validate_bindings` 对照记录索引、角色、名字集合及声明的 endpoint 和时间误差。它没有测量响应时序、验证顺序/缺帧/每轴动态覆盖，也不校准或估算时钟误差。P01-T 采用以下实测责任覆盖这些缺口，并保留 B2 BLOCKED 直到合格。

## 记录合同

C2-RT 与本协议共享 recording/part、设备/控制器身份、序列、采样与到达的证据绑定。一个物理设备或实验的历史身份只允许在各自证据合同成立后使用。P03 启动还依赖独立的 C2-RT、物理 robot-base 注册及 P02 签核。[真实时序补证规格](P01_C_RT_clock_qualification.md)

| 记录 | 最低字段和语义 |
|---|---|
| 采集 manifest | 不可复用 recording ID、episode/part 顺序和哈希、schema SHA、UTC 及 monotonic 域、配置/标定哈希、信号路由、capture 被审人和授权引用、模式如仿真/影子/真机。 |
| 实际命令 | 控制器接收与实际下发分别记录原值、明确 clock domain、序列号、输入请求和安全裁剪后送达的量、单位、控制模式、控制周期、下发确认/拒绝。附 14 个臂轴和每手 20 个轴名称、顺序和映射版本。 |
| 设备测量 | 反馈采样与反馈接收分别记载，带设备序号、环路状态、实测位置、可得的速度/effort/current、单位及有效位。空值保持。标记实测来源、FK/滤波派生和估计，保留原始量和变换。 |
| 时钟与运行日志 | controller monotonic、设备时间、ROS 时钟、MCAP log/publish、采集器 observed clocks 分域。独立同步锚点、触发/观测序号、offset/skew 和实际误差；记录重启、丢帧、过滤、loop overruns、驱动 enable 和安全停机。 |
| 安全和量测 | 记录独立安全操作者的批准引用、日志、停机/看门狗、工位/部件 ID、校准日期/哈希、验证的运动空间和约束配置。可选外部量测时注明实际测到的物理轴和精度。 |

## 补录流程

1. 先离线验证 writer、命名、索引完整性、域描述、缺帧报告及终止日志。对设备脱机或回放条件作负控。
2. 在独立批准的台架完成只读检查。核对工位、模型和标定，确认急停、看门狗、撞限、热/电异常与失联处理。数据脚本限制为记录，现场操作者单独控制运动授权。
3. 若获后续批准，硬件负责人根据实际约束冻结各组轴的低风险试验设计。先取得静态零输入和正常遥测证据，再按审核过的安全区间逐组获取有效动态响应。确保双臂、两手每个可控轴及交互的诊断覆盖，且能区分单轴和耦合响应。使用硬件批准的幅值、速率、时间和停止条件，本文不预设运动参数。
4. 保存同一时钟参考下的实际事件和失配。遇到时钟不连续、失联、指令未确认、信号陈旧、安全触发、测量越界或记录器故障时由现场授权负责人停止。保留故障片段，重新校准后需重新验证。
5. 以版本化只读原包和新 Run ID 发布，原始录包与日志分区访问。沿 parent lineage 去重，轨迹回放不得作为真实响应。复测/重复试验按同一 capture session 记账。终评母源及访问日志独立封存。
