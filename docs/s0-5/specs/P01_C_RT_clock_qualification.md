# C2-RT 真实时序补证规格 v0.1.0

当前 BLOCKED。本规格属于离线设计。只读审计现有资料可执行。任何新现场采集、连接设备、受控动作和发令均需后续单独授权与硬件安全审批。[P01-T 共享采集与安全协议](P01_T_telemetry_acquisition.md)

## 统一记录与绑定

与 P01-T 共用 recording/part SHA、schema SHA、设备与控制器 build/config SHA、时钟域注册表、boot ID、映射版本、原物理索引、消息及源序列号、观测层用途标记。每次采集前注销旧映射并记录频率、同步源、受控范围。所有缺失字段保持 UNKNOWN。

| 事件 | 原始记录及证据 |
|---|---|
| MANUS | packed SDK source 原值和按版本解压组件、SDK receive、设备采样身份、host boot/进程实例、SDK build/SHA；区分 source/重发 |
| Tracker | 原设备时间或离线确认的设备时间区间、对应 OpenVR/driver 实例、原包与注册副本身份、丢帧及质量 |
| 控制器 | 实际 callback 刚进入的 monotonic receive、用于计算的 tick/cutoff、读取的每流唯一原索引、队列与调度日志 |
| 发令和反馈 | issue、独立 applied/ack、真实反馈采样与接收，记录各设备序列、关节映射、来源及置信区间，使用 P01-T 的命令/遥测合同 |
| 时间锚点 | 独立参考设备/时钟、触发与观测配对、仪器校准及误差报告、原始波形/事件、映射斜率界、offset、有效区间、每次重启/跳时/丢帧记录 |
| 物理基座 | 独立测量的 robot-base 与采集世界之间变换，设备/工位/标定 SHA、残差和重复性；与软件注册和 C2-RT 分门 |

## 验证设计

优先使用有独立参考时钟的硬件触发或可复现物理事件，分别绑定设备观测与控制 callback。以同一时间参考的留出锚点和原始波形校验含误差界的映射。每个样本计算 capture、arrival 的上下界并附域、区间、传输、仪器误差和前缀可用锚点。重新启动、失锁、生成号切换、区间外推或锚点矛盾使对应段资格无效。日志重点验证可见性，不能仅凭日志推定设备物理采样时刻。

设备没有直接采样时间时，使用外部高速光学或独立触发仪器将真实运动事件、可识别设备观测和控制器记录绑到共同参考，包含物理事件检出区间、设备曝光或采样周期、同步与匹配误差。若只能建立可追溯输出反应时间，限定为有证范围的外部端到端时延，内部 capture/arrival 若无法界定仍 UNKNOWN。仅单向软件日志、相邻时间差或厂商时间戳名称不足以证明链路延迟。此设计不预设设备支持某种硬件接口。

验证报告必须提供分流及端到端覆盖、有效/失效误差界、残差分位、因果前缀、重复和乱序负控、独立 clock reset 试验和闭环时间证据。提前锁定预算、CI/容差和物理可用范围，禁止用测试结果回调门槛。只有独立证据审核与人工签核完整时才新增 VERIFIED 样本，P01-T 和物理基座仍各自验收。
