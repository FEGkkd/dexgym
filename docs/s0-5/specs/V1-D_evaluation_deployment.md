# V1-D 独立评估、导出与仿真部署实施规格 v2.0.0

## 1. 目标与范围

设计状态为 `DRAFT_READY_FOR_REVIEW`。V1-D 用独立 MuJoCo 闭环选择 Actor，构建可独立推理和仿真运行的发布包，明确功能、性能和真实硬件资格。范围覆盖缓存公平对照、在线 provider 的隔离仿真以及交付。正式独立 Test、真实硬件、完整生产 Teleop 集成与多种子科研主张归后续独立授权。[评估协议](../EVALUATION_PROTOCOL.md) · [运行时契约](V2_runtime_contract.md)

## 2. 前置与输入

须有已签核设计与 V1 整体授权、V1-A/B/C0 及 V1-C1/C2/C3 的技术门和可读结案证据、冻结目标和分母、剩余评估预算以及独立 Reviewer。V1-D 可在性能门未通过时交付已验证的较低等级，前序数据、因果、安全、World Model 与独立审查技术门仍须通过。

输入包含 HMB/RMB/掩码和源 SHA、初态与扰动配对表、训练和独立验证报告、checkpoint/归一化/schema、仿真模型和 Servo、冻结目标、发布主机及现有软件栈可用版本。可并行搭建独立 scorer、导出测试和打包构架，实际候选评估与部署资格依上述前置。

## 3. 输出、数学和作用域

输出完整计划与实际逐帧表、源与方法分层、配对统计、失败及 UNKNOWN、训练期 dev 选择台账、单独发布复验、模型导出/独立运行证据、release manifest、候选技术等级。所有评分遵照 E1–E5。V1 主目标为独立 mapped intent，禁止修改目标、按结果改评分掩码或排除失败。用复合 P95、同拍命中率与失败拍率建立优先准入，再判断功能误差和安全约束。导出等价用最大绝对差和离散决策一致，连续闭环保留原始 tick 时间轴。

## 4. 架构与接口

计划 `eval/paired_rollout.py` 管理统一的 B0/B54 测试入口，`eval/score_release.py` 独立加载目标与事实轨迹，`deploy/export_actor.py` 从冻结 checkpoint 提取 Actor 和归一化状态，`deploy/verify_release.py` 执行文件与启动验证，`deploy/sim_runner` 使用流式人端输入及因果名义 provider。从既有适配器复用有名关节、坐标和消息接口。独立评分进程读取原始事实文件与输入身份，发布包验证进程无训练文件目录访问。每个 Run 使用隔离、不可变输出根和相应 SHA。[运行时契约](V2_runtime_contract.md)

## 5. 实施与实际运行

1. Train 定标和检查器通过后封存评分配置、开发 Validation 配对表、ranking 及预算，冻结全计划分母。
2. 将通过安全、C0 和训练阶段证据检查的 checkpoint 组成最多 6 个候选。先用冻结开发 Validation 做实际 MuJoCo 回放。排除硬安全失败或缺证，以非退化门通过数、静态和共同可改善域相对收益两者的最小值、完整目标域 P95、最后按较早 checkpoint 和 SHA 排序。协定在评价前锁定。无可用相对收益时记录资格不足，仅按有限绝对误差和安全门筛选诊断候选。记录所有候选及失败。
3. 独立 Reviewer 在首选 SHA 固定后进行 B0/B54 实际重放。动态全段只在开始 reset，另跑静态、功能、困难和冻结扰动场景。保存实际时序、错误、退出状态及按阶段预算计量。首选的发布复验失败，保留原结论，按治理规则进行有界修复。资格以最近完整复验判定。
4. 导出并在训练进程之外验证 I/O 和归一化等价，随后在隔离仿真流式主机验证现有 Marvin IK + Wuji SDK 名义适配、回退、关闭 residual 和启动失败负控。容差与采样见参数登记。
5. 封存候选等级、具体运行配置及证据，独立 Reviewer 复核同一候选和一致的哈希。实际运行要留下可重放的命令和返回码，进入整个 Campaign 的 `READY_FOR_REVIEW`。

## 6. 测试与定量协议

| 层次 | 正负控与验收 |
|---|---|
| 单元 | scorer 的分位数、无目标、非法反馈、失败尾段、配对根及零/非有限 baseline；坐标与有名轴、mask、history、离散事件和数值容差；Actor 格式、篡改 manifest、配置错配、训练组件不可达。 |
| 集成 | 合法输入 residual-disabled/B0 请求到反馈等价，非法 reset、输入时序与前缀、碰撞/非有限请求、deadline、worker 崩溃、仿真状态机安全路径。 |
| 真实仿真运行 | B0/B54 独立实际回放，至少两次可重复启动，按预注册窗口完成连续闭环，暴露训练/在线名义分布差异。报告训练导出输出差、实际发令与反馈、仿真时钟和预算。 |
| 独立验证 | 从 release manifest 重算全部 SHA，任取冻结真实仿真回放复算主门与失败掩码，独立运行推理和至少一段受控注入演练。 |

定量主门使用 E4，常规静态/动态与功能分层须满足预登记最小支持数。有时钟资格和旧系统同配置约束，才报告生产 Teleop 旁路资格。所有 B14、PPO、新联合 IK 及旧 S0-4 比较独立列预算、正常执行范围与实际状态。证据目录建议 `v1/<campaign_id>/V1-D/<run_id>/`，包括 `gate_receipt.json`、`paired_plan.json`、`score_manifest.json`、`coverage.json`、`parity.json`、`timing.json`、`failures.jsonl` 及 `release_manifest.json`。

## 7. 预算、验收与等级

从 Campaign 共同实际评估池最多 200 万 MuJoCo transitions 计费，候选分配 65 万给 V1-D，包含复验、试运行和恢复重试。全程 1 GPU、48 GPU 小时、72 小时总经过时间（资源等待总计最多 24 小时）、250 GiB 净新增存储上限。B14 不含在提议首版预算。启动前确认有足够余额复核发布候选，耗尽则记录证据缺口与可确认等级。[预算治理](../MULTI_AGENT_PROTOCOL.md)

| 等级 | 证据 |
|---|---|
| `EXPORTABLE` | 合法训练 Actor checkpoint 存在且已导出，release manifest 验证通过。 |
| `SIM_DEPLOYABLE` | 以上要求及独立推理、因果性、运行时接口、硬安全和回退、连续闭环仿真实测通过。 |
| `SIM_RECOMMENDED` | 以上要求及冻结 V1 收益、覆盖和非退化门全部通过。仅提交技术候选供人工验收。 |
| `REAL_DEPLOYABLE` | 正式真实物理基座、时钟、遥测、Servo、安全、独立外测计量及现场人工批准全部满足，逐级 Shadow/HIL/实机证据具备。进入独立后续流程。 |

通过流程证据可完成阶段审核并携带较低等级；账本记录实际资格和性能门未过原因。任何失败妨碍安全门时停止仿真推荐与下游发布。无真实训练权重则无部署等级。独立 Reviewer 的实际复核和硬安全应答是仿真部署资格条件。

## 8. 失败、风险、复现与下游

数值不一致时按字段、归一化、dtype、指序、软件依赖、Servo 和时钟顺序定位，修订合同后使受影响签核失效并重新验收。没有合法候选、启动失败、命令越界或资料缺失时保留首个失败的原始输出、退出码、重试预算、负责人和后续建议。主要风险为缓存因果参考与在线名义分布偏移、仿真/实际 Servo 不同、故障注入低覆盖和开发数据反复使用。采用冻结配对、独立流式验证、完整失败披露和封存独立 Test 管理风险。

交付物为 Actor 候选及可验证等级证据、配对评估、复现清单、独立验证、版本化源码与依赖、SHA、有效范围及剩余问题。重放需记录主机、命令、git SHA、模型与配置、输入和样本 seed、物理/实时路径、端口或隔离域、日志、包哈希、硬件资格引用。完整生产集成、外部计量及独立终评各以单独授权和证据进入后续流程。[评估协议](../EVALUATION_PROTOCOL.md)

## 9. 恢复及后续验收

中断时核对已完成配对、候选与运行时 SHA、恢复点和预算。完整动态轨迹按单初态重新开始，原失败或未完成拍留存。全部 V1-D 技术材料由独立 Reviewer 核查后提交用户。生产 Teleop 和真实部署沿各自后续资格办理。
