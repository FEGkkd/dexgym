# Robot Dynamics Adapter guide

Implement `RobotDynamicsAdapter` in `source/dexgym/algorithms/supermimic/interfaces/robot.py` and provide an immutable `RobotSpec`. Register a constructor with `PluginRegistry.register_robot`. No Core file should import that implementation.

The adapter must provide `integrate(state, predicted_physical_delta, action, context)`, `physical_delta(state, real_next_state)`, `executed_command(state, action)` and `physical_state(env)`. `integrate` must remain differentiable through state and action; it must reproduce the real controller's analytic command update. Set `state_dim`, `action_dim`, `delta_dim`, `context_dim`, `action_schema`, `state_schema`, policy/physics dt, asset SHA and joint order. If task dynamics depend on contact, objects, changing payload or actuator settings, extend state/context or train a separate world model. Reusing weights on an incompatible contract is unsupported.

Marvin's adapter is [`core_plugins.py`](../../source/dexgym/tasks/marvin_supermimic/core_plugins.py). Its state is `[q_arm14, qd_arm14, q_cmd14]`; the learned 28D delta changes only `q, qd`. The unchanged [`robot_adapter.py`](../../source/dexgym/tasks/marvin_supermimic/robot_adapter.py) owns the 50 Hz to 500 Hz command interpolation, actuator limits, action origin/scale and differentiable FK. `legacy_wave_v1` retains the Wave-specific origin/scale only for old checkpoints. New Reach uses `robot_fixed_v3`; its 0.25 rad operating envelope must be changed by introducing a new action schema when a task exceeds it. The full Newton articulation retains all 54 joints, with 40 fingers fixed at Home under the validated hand-contact configuration.

Before connecting a new robot, test action-map equality between the adapter and physical controller, state extraction before reset, state integration gradients, bounds, asset fingerprint, control frequency and a short physical trajectory. The `RobotSpec` can have any positive dimensions; the Toy adapter exercises 2D state/1D action in the same Core.
