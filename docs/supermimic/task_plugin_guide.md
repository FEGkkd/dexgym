# How to add a SuperMimic task

1. Select an existing `RobotDynamicsAdapter` with the **same** state, action and controller contract, or implement a new one. Do not share world-model weights across an unmodelled payload/contact change.
2. Define a `TaskSpec`: observation width/history, goal width/horizon, typed task-data width, Critic feature width, schema identifiers and optional learned-termination feature width.
3. Implement `TaskMDP` methods in [`interfaces/task.py`](../../source/dexgym/algorithms/supermimic/interfaces/task.py): `advance`, `observation`, `goal`, `critic_features`, arrival `reward`, `soft_termination`, `hard_termination`, `valid_imagination_start`, `success_mask`, `evaluate_metrics`, and `checkpoint_contract`. Set `success_hold_steps` explicitly. Return finite tensors with declared widths. Keep reward and soft termination differentiable. The checkpoint contract must include actual Reward weights, termination thresholds, Episode and success definitions, not merely tensor dimensions.
4. If tracking a clip, use `MotionLibrary.reference_at` for arrival reward/termination and `future_goal_at` for the Actor. Non-50 Hz clips are rejected until an SO(3)-aware importer exists. Static-goal tasks can put the target in `TaskState.data` and use motion ID `-1`.
5. Provide an actual physical collector/environment producing a pre-reset `TransitionBatch`. [`core_collector.py`](../../source/dexgym/tasks/marvin_supermimic/core_collector.py) can be reused for compatible Marvin Newton environments. The Robot Adapter must return `dynamics_context(native_env)` at action time, including `[N,0]` when empty. If context evolves during an Episode, declare `context_evolution="adapter_transition"` and provide `next_dynamics_context`. The environment must report Task Reward and hard termination at arrival; the collector checks Reward, termination, executed command, observation history and reference time.
6. Register the robot and task in a plugin registration module. Marvin's two task IDs are registered in [`register_core.py`](../../source/dexgym/tasks/marvin_supermimic/register_core.py).
7. Supply a JSON configuration with separate `algorithm`, `robot`, `task` and `environment` sections. The examples are [`m43_tracking_smoke.json`](../../configs/supermimic/m43_tracking_smoke.json) and [`m43_reach_smoke.json`](../../configs/supermimic/m43_reach_smoke.json). `NetworkFactory` derives all widths from the two specs. The same `SuperMimicTrainer` and `PhysicalEvaluator` then run both tasks.
   Optional task-level `observation_noise` declares per-feature units and scales; see [the M4.3.2 contract](observation_noise_contract.md). Core Newton environments must disable native observation noise to avoid an inconsistent Actor sensing path.
8. Run mathematical/schema tests, a bounded real-physics smoke, independent evaluation, and `CoreCheckpoint` save/load. Use `fresh_physics` for Newton continuation; request `full` only when the collector can export and restore exact physical state. Run `scripts/supermimic/isaac_runtime.py evaluate_core_m431` in a new process for one-Episode-per-environment metrics and a trace. Export a PyTorch Actor with `export_policy`, then verify `InferencePolicy.act` against the original Actor and action map. Export is software inference only.
   Training resume is strict; independent evaluation may explicitly change seed, environment count and reset protocol while preserving the immutable execution contract. See [evaluation protocol](evaluation_protocol.md). Sharing World Model weights across tasks requires an explicit Robot Adapter [dynamics signature](world_model_sharing_contract.md) and one common World Model optimizer.

The Tracking plugin uses 10×90 six-link future goals, 10×56 proprio history and 146D Critic features. The Reach plugin uses a **static 1×6 dual-TCP position goal**, 4×48 history, its own reward, safety termination and TCP distance/success metrics. Reach uses the procedural reference only to initialize a safe full-body Newton pose; the six-link trajectory is not its goal. Toy tests use 1D and 2D goals and a 2D/1D robot.

Both Marvin tasks inherit the shared `MarvinArmNewtonBaseEnv` physics layer directly. Tracking owns MotionManager, reference frame advancement and tracking Reward. Reach owns static TCP target, Reach Reward and its Episode clock. New tasks should extend the base only when they use the same pinned 54DoF asset and servo contract; a different robot supplies its own physical adapter/environment. The SuperMimic Core Trainer is unchanged.

Adding another task with an existing robot requires a task plugin, task config and appropriate physical environment/collector. The Core world model, Replay, imagination, return math, optimizer and Trainer do not change. Different TaskSpecs can run sequentially through the same Trainer implementation; a single mixed batch with incompatible TaskSpecs is not supported. Synthetic tests exercise two Motion IDs and different clip lengths inside one Trainer, but the current Newton environment still binds one MotionManager to its whole environment batch. Simultaneous Wave-plus-Procedural Newton mixing is therefore **not validated**.
