# Checkpoint and inference compatibility

M4.3.1 `CoreCheckpoint` writes `supermimic_core_v2` atomically. The record contains the exact RobotSpec, TaskSpec, TrainerConfig, termination mode, network state signatures and weights, optimizer/scheduler states, all RunningNorm buffers, training counts, Git SHA, reference hashes, physics configuration and Torch/NumPy/Python/CUDA RNG. A readable canonical contract manifest and SHA256 bind the complete NetworkSpec, actual Goal Tanh switch, normalization modes/floors/count limits, world-model integration/output versions, robot action origin/scale/bounds/slew/interpolation, controller source gains and effort ranges, task Reward profile/weights, termination thresholds, episode and success semantics, and reset asset SHA. The loader reports the first conflicting field path when two same-shaped models have different semantics. Model weights load with `strict=True`.

Resume mode is explicit. `fresh_physics` is the default: models, optimizers, normalizers and RNG load, but Replay and collector do not; trust is cleared and Newton must collect fresh real transitions. `replay` retains historical Replay while a new physical collector starts a **new Episode ID**; trust is cleared. `full` requires a collector with both state export and import, and save fails immediately if state is unavailable. Toy supports exact Full Resume. The Newton collector has no exact simulator-state restore, so Newton uses `fresh_physics`; its checkpoints do not claim bitwise physical continuation. All modes clear old model trust before BPTT.

`CoreCheckpoint.load` rejects changed action/state/goal/observation schemas, network widths or activations, Reward or Termination parameters, normalizer settings, controller/effort configuration, reference or physics fingerprints, and optimizer/scheduler set. An M4.3 v1 checkpoint lacks activation and task semantics; v2 never silently loads it. `load_legacy_m43_v1_actor_for_evaluation` is an **explicit evaluation-only** path requiring the source Git SHA, reference/physics fingerprints and acknowledged Tanh/normalization assumptions. Its Actor output was compared with the original M4.3 source process. M4.1 remains on `load_legacy_m41_actor` and the historical full Wave evaluator. M4.2 remains on `load_legacy_m42_actor` with exact tracking/reference/asset checks.

| Artifact | Same Robot/Action/Task contract | Allowed use |
| --- | --- | --- |
| M4.3.1 v2 Core checkpoint | Exact readable manifest and SHA256 match | `fresh_physics`, `replay`, or `full` only when collector supports it; strict Actor evaluation |
| M4.3 v1 Core checkpoint | Shapes and legacy fingerprints match, unrecorded semantics acknowledged | Explicit Actor evaluation only; no implicit v2 resume |
| M4.2 Procedural Actor | Historical M4.2 schema/reference/asset match | Legacy evaluation through its strict loader |
| M4.1 selected_best.pt | Legacy Wave action/goal/reference match | Legacy Actor and full Newton Wave evaluation |
| Different action schema, controller, goal, reward or termination | Any conflict | Reject; train or explicitly migrate a new model |

Two tasks may share World Model weights only when state, action, controller and context contracts all match. Neither a different robot nor a changed payload/contact domain is implied compatible by matching tensor widths.

`export_policy` writes `supermimic_pytorch_policy_v1` with Actor weights, normalizers, RobotSpec/TaskSpec/NetworkSpec, action schema, joint order, 50 Hz frequency, asset/reference hashes and policy SHA256. Export now rejects a supplied NetworkSpec that differs from the executing Actor, including same-shaped Tanh/normalizer changes. `load_policy` verifies SHA and optional expected robot/task schema. `InferencePolicy.act(history, goal, state, robot_adapter)` returns raw action and executed command. CPU/GPU PyTorch consistency is tested. This artifact is software inference only; it is not a full task/physics resume or real-hardware deployment approval.
