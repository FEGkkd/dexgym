# Checkpoint and inference compatibility

`CoreCheckpoint` writes `supermimic_core_v1` atomically. The record contains exact RobotSpec, TaskSpec, TrainerConfig, termination mode, network state signatures and weights, optimizer/scheduler states, all RunningNorm buffers, training counts, allowed horizon and trust report, Git SHA, reference hashes, physics configuration and Torch/NumPy/Python/CUDA RNG. Replay and collector state are optional. Toy saves both and a test resumes the episode-safe ring; Newton smoke saves no Replay because a new process cannot safely resurrect its physical simulator state. Loading such a checkpoint explicitly returns `requires_fresh_collection=true`. Every load clears the old trust horizon, forcing new held-out real-data validation before BPTT.

`CoreCheckpoint.load` rejects a changed action/state/goal/observation schema, network width, reference or physics fingerprint, optimizer/scheduler set, or a Replay that cannot be resumed by the physical collector. It does not use `strict=False` for models. The M4.1 Actor is loaded only by `load_legacy_m41_actor`, with the pinned Wave reference SHA. `load_legacy_m42_actor` checks the exact M4.2 six-link tracking schema, reference SHA and robot asset SHA; the M4.2 Procedural checkpoint was actually loaded in the M4.3 test. Old checkpoints are never migrated into the new network shape implicitly.

`export_policy` writes `supermimic_pytorch_policy_v1` with Actor weights, normalizers, RobotSpec/TaskSpec/NetworkSpec, action schema, joint order, 50 Hz frequency, asset/reference hashes and policy SHA256. `load_policy` verifies SHA and optional expected robot/task schema. `InferencePolicy.act(history, goal, state, robot_adapter)` returns both raw action and executed command. CPU/GPU PyTorch consistency is tested. This artifact is not a real-hardware deployment approval.
